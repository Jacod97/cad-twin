무엇을 만드는가

CAD 배치도에는 선, 호, 블록, 글자만 들어 있습니다. 물건이 어느 방향으로 흐르는지, 어디서 합류하고 어디서 갈라지는지, 레인이 루프와 만나는 곳이 연결인지 위로 지나가는 다리인지는 도면에 적혀 있지 않고 사람이 도면을 보고 해석해야 알 수 있습니다. 3D 모델을 만드는 사람과 시뮬레이션 모델을 만드는 사람이 이 해석을 각자 따로 다시 하는 것이 보통입니다.

이 프로젝트는 해석을 한 번만 합니다. 도면을 읽어 설비 목록과 연결 관계(equipment.json)를 만들고, 3D 장면과 시뮬레이션 모델을 둘 다 이 목록에서 만듭니다. 그래서 구간 이름 CV1633은 도면의 이름표, 3D 장면의 물체, 시뮬레이션 결과의 행에서 모두 같은 컨베이어를 가리킵니다.

데모가 보여주려는 것

  • DXF 배치도에서 컨베이어 191구간, 제어반, IoT 센서를 자동으로 뽑아낸다.
  • 뽑아낸 목록으로 실제 크기의 3D 공장 장면(USD)을 만든다. 실제 설비 3D 에셋(NVIDIA SimReady)을 도면 치수에 맞춰 배치한다.
  • 같은 목록으로 이산 사건 시뮬레이션(SimPy)을 돌려 구간별 처리량, 대기 시간, 점유율을 계산한다.
  • 결과를 3D 장면에 색으로 입혀 병목이 생기는 위치를 공간에서 바로 본다.
  • 맥 미리보기(USDZ)와 브라우저(Omniverse 스트리밍)로 결과 장면을 연다.

도면만으로 정해지지 않는 값(컨베이어 폭, 제어반 높이, 속도, 도착률 등)은 사람이 설정 파일 두 개에 적습니다. 값을 바꾸고 스크립트를 다시 돌리면 장면과 결과가 새로 만들어집니다.

전체 흐름

각 단계는 draft/ 안의 스크립트 하나이고, 앞 단계가 만든 파일을 읽어 다음 파일을 씁니다. 단계 번호는 스크립트 이름의 번호를 그대로 썼습니다(3번 스크립트는 없습니다). 도면 해석 결과 하나가 3D 장면과 시뮬레이션 두 갈래로 나뉘었다가, 결과를 입히는 단계에서 다시 만납니다. 그림의 실선은 데이터 파일의 흐름, 점선은 사람이 값을 적는 설정 파일입니다.

좁은 화면에서는 그림을 옆으로 밀어 볼 수 있습니다.

입력 도면

입력은 공개 샘플 도면 conveyor-system-sorting-lane-plan-with-control-points(DWG 원본과 DXF 변환본, data/)입니다. 물품이 세 줄의 인입 라인으로 들어와 하나의 메인 라인으로 합쳐지고, 재순환 루프를 돌다가 아홉 개의 분류 레인 중 하나로 빠지는 분류 설비입니다.

도면에 들어 있는 것

  • 컨베이어 중심선: 레이어 0의 LINE과 ARC. 폭 정보는 없습니다.
  • 구간 경계: 중심선에 직각으로 그은 200 mm 짧은 선.
  • 구간 이름표: 블록 name의 TAGNUMBER 191개. 구간 191개와 1:1로 대응합니다.
  • IoT 센서: 블록 IOT. 구간마다 하나씩 놓인 점입니다.
  • 제어반: 블록 CP…(사각형 외곽과 문 열림 호)와 글자 CPn.

라인 구성

이름표의 앞 두 자리가 라인을 나타냅니다. 흐름 방향은 같은 라인 안에서 번호가 커지는 방향으로 해석했습니다.

도면만으로 정해지지 않아 사람이 정한 해석

아래 네 가지는 도면을 아무리 봐도 답이 하나로 나오지 않아서 사람이 결정했고, config.yaml의 interpretation 항목에 적혀 있습니다.

  • 교차는 입체 교차. 16xx 레인은 15xx 루프 위쪽을 접합 표시 없이 가로지릅니다. 물품이 여기서 섞이지 않는다고 보고, 레인이 루프 위로 지나가는 다리로 처리했습니다.
  • 평행 레인은 측면 이송. 각 레인 옆의 짧은 평행 레인(16x6–16x7)은 어디에도 이어져 있지 않습니다. 옆 레인의 16x4 구간에서 옆으로 밀어 넣는 것으로 해석했습니다.
  • 흐름 방향은 번호 증가 방향. 도면에 화살표가 없어서 이름표 번호가 커지는 쪽으로 흐른다고 봤습니다.
  • 100 mm 어긋남은 작도 오차. 16xx 레인 중간에 중심선이 100 mm 어긋난 곳이 있는데, 실제 설계가 아니라 그릴 때의 오차로 보고 이어 붙였습니다.

STEP 2 · s2_build_scene.py, s2_render.py3D 장면: 설비 목록을 실제 크기의 공장으로

설비 목록의 구간마다 실제 컨베이어 3D 에셋을 하나씩 놓아 USD 장면 out/scene/factory.usda를 만듭니다. 좌표는 도면 좌표(mm)에서 원점을 빼고 1000으로 나눈 미터 단위이고, 위쪽이 Z축입니다.

배치 규칙

  • 직선 구간: NVIDIA SimReady 에셋 warehouse_conveyorBelt_a05(길이 2.0 m, 프레임 폭 1.15 m, 롤러 상면 0.769 m)를 시작점에 놓고 진행 방향으로 돌린 뒤, 길이와 폭을 구간 치수에 맞게 늘이거나 줄입니다.
  • 90° 곡선: 에셋 warehouse_conveyorBelt_a02를 곡률 반지름 비율로 균일하게 키웁니다. 왼쪽으로 도는 곡선은 오른쪽 곡선을 끝점에서 거꾸로 놓아 만듭니다.
  • 60° 곡선: 맞는 에셋이 없어서 같은 규약의 단순 곡선판을 프로그램으로 만들었습니다.
  • 합류·분기 접합부: 상대 컨베이어 폭의 절반만큼 직선 끝을 잘라 서로 겹치지 않게 합니다.
  • 입체 교차: 교차하는 16x3 구간의 롤러 상면을 2.0 m로 올리고, 앞뒤 두 구간씩을 경사로로 만들어 연결하고, 1.2 m 간격으로 지지 기둥을 세웁니다.
  • 제어반: 도면의 평면 크기대로 상자를 만들고 문 쪽 면을 표시합니다. 높이는 도면에 없어서 1.8 m(작은 것은 1.2 m, 1.0 m)로 가정했습니다. 컨베이어와 겹치게 그려진 제어반(CP8, CP16–CP24 등)은 옆으로 밀어 두고 옮긴 거리를 기록했습니다.
  • IoT 센서: 바닥에서 1.0 m 높이의 작은 구로 표시합니다.

장면 안에 남기는 정보

각 컨베이어는 /World/Conveyors/L16xx/CV1633처럼 라인별로 묶이고, 이름표 번호, 라인, 종류, 길이, 폭, 위·아래 구간, 교차 상대, 원래 도면 좌표를 cadtwin:* 속성으로 함께 갖습니다. 3D 장면만 열어도 각 물체가 도면의 어느 구간인지 알 수 있습니다. 같은 에셋은 한 번만 읽고 재사용(instanceable reference)하므로 직선 182구간이 메시 하나로 그려집니다.

도면과 맞는지 확인하는 방법

3D 장면을 위에서 원근 없이 렌더한 뒤 원본 도면 선을 빨간색으로 겹칩니다. 빨간 중심선이 렌더된 컨베이어 가운데를 지나고, 빨간 제어반 외곽이 회색 상자와 겹치면 배치가 도면과 맞는 것입니다. 화면이 없는 서버에서 GPU로 직접 렌더해서(pyrender, EGL) PNG로 확인했습니다.

그림 7완성된 3D 장면. 가운데 그림에서 분류 레인이 경사로를 타고 2.0 m 높이로 올라가 루프 위를 지나고, 지지 기둥이 받치는 모습을 볼 수 있습니다. 회색 상자는 제어반, 노란 점은 IoT 센서입니다.

STEP 4 · s4a_build_sim_model.py, s4b_run_sim.py, s4c_color_scene.py시뮬레이션: 같은 목록으로 물류 흐름 계산

Step 1의 연결 관계를 그대로 시뮬레이션 그래프로 옮깁니다(out/sim_model.json). 구간 191개가 노드, 연결 191개가 간선이고, 인입 3곳과 출구 18곳이 있습니다. 루프는 37구간짜리 순환 하나이고, 인입에서 가지 못하는 출구는 없는 것을 확인했습니다. 이 그래프에 sim_config.yaml의 값을 넣어 SimPy로 실행합니다.

모델 규칙

  • 구간 하나는 물품이 쌓일 수 있는 칸입니다. 담을 수 있는 개수는 구간 길이를 물품 간격(1.1 m)으로 나눠 올림한 값이고, 통과 시간은 길이 ÷ 속도입니다.
  • 다음 구간에 자리가 날 때까지 지금 구간의 자리를 붙잡고 기다립니다. 그래서 한 곳이 막히면 정체가 뒤로 번집니다.
  • 합류 지점에서는 먼저 온 물품이 먼저 들어갑니다. 분기에는 1.0초, 측면 이송에는 1.5초의 동작 시간이 더 걸립니다.
  • 물품은 목적지까지 최단 경로로 갑니다. 목적 레인이 꽉 차 있으면 루프를 한 바퀴 더 돕니다.
  • 출구에서는 물품을 하나씩 처리합니다(평균 4초, 지수분포).

병목이 CV1633에서 생기는 이유

CV1633은 전체의 45%, 시간당 약 810개를 받습니다. 출구가 물품 하나를 평균 4초에 처리하므로 이 출구가 감당할 수 있는 최대량은 시간당 900개이고, 부하율이 약 90%가 됩니다(측정 점유율 0.915, 처리 805개/h). 처리 시간이 들쭉날쭉하기 때문에 출구 앞에 줄이 생기고, 그 줄이 레인을 따라 CV1632 → CV1631 → CV1630 → CV1629로 번집니다(평균 대기 5.5초 → 3.8초).

레인이 가득 차면 CV1633으로 가야 할 물품이 루프를 한 바퀴 더 돕니다. 7.5시간 동안 3,058회, 시간당 약 408회이고, 루프를 닫는 구간 CV1537의 처리량(시간당 407.9개)과 같습니다. 체류 시간이 길게는 880초까지 늘어나는 것도 이 때문입니다.

서버에는 화면이 없어서 결과 장면을 보는 방법을 두 가지로 만들었습니다.

맥 미리보기용 USDZ 파일

결과 장면을 맥 Finder에서 스페이스바로 바로 열 수 있는 .usdz 한 파일로 묶습니다. 맥의 Quick Look이 읽을 수 있도록 상자·구 같은 도형을 메시로 바꾸고, 색을 Quick Look이 이해하는 재질(UsdPreviewSurface)로 옮기고, 텍스처를 1024 px JPEG로 줄이고, 위쪽 축을 Z에서 Y로 돌립니다.

파일크기내용
factory_sim_full.usdz19.3 MBSimReady 에셋 형상 그대로. 컨베이어 한 구간이 약 21만 삼각형이라 재사용을 지원하지 않는 뷰어에서는 무겁습니다.
factory_sim_lite.usdz0.48 MB컨베이어를 회색 판과 다리로 단순화. 결과 색 띠, 제어반, 지지 기둥, IoT 표시는 같습니다.

브라우저에서 보는 Omniverse 스트리밍

NVIDIA Omniverse Kit 106.0.3으로 만든 뷰어 앱(cadtwin.viewer_streaming)이 서버 GPU에서 factory_sim.usda를 렌더하고, NVIDIA의 web-viewer-sample로 만든 웹 페이지(포트 5173)가 그 화면을 브라우저로 받아 보여줍니다. 실행과 종료는 omniverse/의 스크립트 세 개로 합니다.

알려진 한계

3D 장면

  • 곡선 에셋은 가로세로를 같은 비율로만 키울 수 있어서 폭을 따로 맞추지 못합니다. 반지름 1040 mm에서 폭이 우연히 0.80 m로 맞았습니다. 60° 곡선은 단순 곡선판입니다.
  • 715–930 mm의 짧은 구간은 2 m 직선 에셋을 길이 방향으로 많이 줄여서 롤러가 촘촘해 보입니다.
  • 경사로의 최대 기울기는 약 23°입니다(두 구간으로 1.23 m를 오르내림). 기울인 에셋은 다리까지 함께 기울어 보입니다.
  • 제어반 높이는 도면에 없는 가정값이라 현장 확인이 필요합니다.

시뮬레이션

  • 구간을 물품이 쌓이는 칸으로만 봅니다. 가속과 감속, 물품마다 다른 크기, 실제 제어 로직(분기 판단, 우선순위)은 들어 있지 않습니다.
  • 속도, 도착률, 목적지 비율, 처리 시간은 모두 데모용 가정값입니다. 결과 숫자는 이 설비의 실제 성능이 아니라 파이프라인이 동작하는 방식을 보여줍니다.

다시 실행하기

conda 환경 torch_render에서 실행합니다(추가 설치: matplotlib, simpy, pyrender, PyOpenGL, trimesh). 스크립트는 순서대로 돌리면 되고, 모든 결과는 draft/out/에 다시 만들어집니다.

PY=/disk2/jaesik/miniconda3/envs/torch_render/bin/python
cd draft
$PY s1_analyze_dxf.py        # DXF → out/equipment.json
$PY s1_plot_plan.py          # → out/s1_plan_*.png
$PY s2_build_scene.py        # → out/scene/factory.usda
$PY s2_render.py             # → out/s2_*.png
$PY s4a_build_sim_model.py   # → out/sim_model.json (+ sim_config.yaml, 없을 때만)
$PY s4b_run_sim.py           # → out/sim_results.json, .csv
$PY s4c_color_scene.py       # → out/scene/factory_sim.usda, out/s4_*.png
$PY s5_export_usdz.py both   # → out/factory_sim_full.usdz, factory_sim_lite.usdz
사람이 고치는 파일들어 있는 값
draft/config.yaml컨베이어 폭, 도면 해석 규칙(입체 교차, 측면 이송), 에셋 경로, 제어반 높이, IoT 표시, 입체 교차 높이와 경사로 길이
draft/sim_config.yaml실행 시간, 속도, 물품 길이와 간격, 분기·측면 이송 시간, 인입 도착률, 목적지 비율, 출구 처리 시간

이 보고서의 숫자는 draft/out/equipment.json, sim_model.json, sim_results.json과 두 설정 파일에서 가져왔습니다. 그림과 출구별 처리량 그래프는 python3 report/build_report.py가 draft/out/에서 읽어 이 파일 안에 직접 넣습니다. 스크립트를 다시 돌린 뒤 이 명령을 실행하면 HTML과 PDF가 함께 새로 만들어집니다.
